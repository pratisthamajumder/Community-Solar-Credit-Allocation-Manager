# Work Breakdown Structure (WBS)

## 1. Requirements Engineering

### 1.1 Problem Analysis
- Study the problem statement.
- Identify stakeholders and actors.
- Identify system boundaries.

### 1.2 Requirements
- Define functional requirements.
- Define non-functional requirements.
- Identify assumptions and constraints.
- Prepare requirements traceability.

## 2. Architecture

### 2.1 Component Identification
- Identify the user interface.
- Identify business/application services.
- Identify telemetry service.
- Identify data storage.

### 2.2 Architecture Design
- Select architecture style.
- Identify interfaces.
- Create UML component diagram.
- Prepare written justification.

## 3. Project Creation

### 3.1 Repository Setup
- Create GitHub repository.
- Create required folders.
- Add README.
- Commit and push initial documentation.

### 3.2 Evidence
- Capture required project-creation screenshots.
- Capture repository structure.
- Capture relevant commit history.

## 4. SRS and Planning

### 4.1 SRS
- Define purpose and scope.
- Define users.
- Document functional requirements.
- Document non-functional requirements.
- Document use cases.
- Document security and performance requirements.

### 4.2 Work Breakdown
- Divide project activities into manageable tasks.
- Map tasks to requirements and architecture.
- Review completeness.

## 5. GitHub Copilot Activity

### 5.1 Task Definition
- Select a small coding task related to the project.

### 5.2 Copilot
- Write a clear prompt.
- Generate a code suggestion.
- Review the suggestion.
- Modify/refine the code where necessary.

### 5.3 Verification
- Run tests.
- Record results.
- Document bugs and corrections if any.
- Capture required Copilot evidence.

## 6. Final Review

- Verify all required deliverables.
- Check file names.
- Check repository structure.
- Verify traceability.
- Review screenshots.
- Push final version to GitHub.
